# Security Policy

## Reporting a Vulnerability

Please do not disclose security vulnerabilities through public GitHub issues.

If you discover a security issue, please contact the repository owner privately through GitHub with:

- A clear description of the vulnerability
- Steps to reproduce the issue
- Potential impact
- Any relevant logs, screenshots, or proof-of-concept details

Please avoid including real credentials, personal data, or other sensitive information in reports.

## Scope

Security reports involving authentication, authorization, exposed secrets, unsafe file handling, API access, dependencies, or other vulnerabilities in this project are welcome.

## Response

Security reports will be reviewed as soon as reasonably possible. Please allow time for investigation and remediation before publicly disclosing the issue.

## Best Practices for Contributors

- Never commit passwords, API keys, tokens, private keys, or `.env` files.
- Use environment variables for sensitive configuration.
- Remove sensitive data from logs and issue reports.
- Keep dependencies and deployment configuration up to date.
